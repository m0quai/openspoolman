## Verifizierter Hardwarestand

Ein GERUI/Elechouse-kompatibler PN532 V3 läuft am ESP32-S3 über I2C1:

| PN532 | ESP32-S3 |
|---|---|
| VCC | 3.3 V |
| GND | GND |
| SDA | GPIO8 |
| SCL | GPIO9 |
| IRQ | nicht verwendet |
| RSTO | nicht verwendet |

```text
PN532 erkannt.
Chip-ID: 0x32
Firmware: 1.6
Ist PN532: True
```

## Passive-Scan

`ListPassiveTarget(MaxTarget.One, TargetBaudRate.B106kbpsTypeA)` funktioniert.

`Pn532.ReadTimeOut` verkürzt den ungefähr fünf Sekunden dauernden Leer-Scan nicht. Der wirksame Parameter ist `MaxRetryPassiveActivation` in `MaxRetriesMode`.

```csharp
var retries = new MaxRetriesMode
{
    MaxRetryAnswerToReset = 0x00,
    MaxRetryPSL = 0x00,
    MaxRetryPassiveActivation = 0x00
};

pn532.SetMaxRetriesInitialization(retries);
```

`0x00` bedeutet einen Aktivierungsversuch ohne Retry. `0x01` kann für etwas höhere Erkennungssicherheit verwendet werden.

## Tagtyp-Erkennung

Der Tagtyp wird nicht nur anhand der UID-Länge bestimmt.

Für NTAG21x wird NXP `GET_VERSION` (`0x60`) über `Pn532.Transceive()` verwendet. Daraus werden NTAG213, NTAG215 und NTAG216 unterschieden.

Die Anwendung verwendet ein eigenes `NfcTagType`-Enum. Weil `Enum.ToString()` auf dem verwendeten nanoFramework den Namen nicht zuverlässig liefert, wird für die Textausgabe eine explizite `GetTagTypeName(NfcTagType)`-Switch-Methode verwendet.

## NTAG215 lesen

NTAG21x `READ` verwendet:

```text
0x30 <StartPage>
```

Ein READ liefert vier Pages = 16 Byte.

Die Library verwendet dafür:

```csharp
pn532.Transceive(
    targetNumber,
    send,
    receive,
    NfcProtocol.Mifare);
```

`NfcProtocol.Mifare` ist hier der von der Library verwendete Protokollweg für die NTAG-Type-A-Kommandos. AMSHelper behandelt den NTAG215 dadurch nicht als MIFARE Classic.

### Praktisch gelesener NTAG215

```text
Page 0: 04-CE-9C-DE
Page 1: 34-D8-2A-81
Page 2: 47-48-00-00
Page 3: E1-10-3E-00
```

Der Capability Container `E1-10-3E-00` auf Page 3 bestätigt den erwarteten NTAG215-Speicheraufbau zusätzlich zur GET_VERSION-Erkennung.

## NDEF – aktueller Schritt

Als Nächstes wird ab Page 4 gelesen:

1. NDEF-/User-Bereich lesen
2. TLV `0x03` (NDEF Message) finden
3. NDEF Record dekodieren
4. URI-Record Typ `U` dekodieren
5. danach eigene AMSHelper-URL als NDEF schreiben

MIFARE Classic ist nicht Bestandteil der Zielimplementierung. Das Projekt bleibt bei PN532 + NTAG215.
